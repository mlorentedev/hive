## Requisitos Previos

- Un cliente compatible con MCP — [Claude Code](https://docs.anthropic.com/en/docs/build-with-claude/claude-code/overview), [Codex CLI](https://github.com/openai/codex), [Gemini CLI](https://github.com/google-gemini/gemini-cli), [GitHub Copilot](https://code.visualstudio.com/docs/copilot/chat/mcp-servers), [Cursor](https://cursor.com/), [Windsurf](https://windsurf.com/), o cualquier otro host MCP
- Un vault de [Obsidian](https://obsidian.md/) (o cualquier directorio de archivos Markdown) — consulta [Estructura del Vault](/hive/es/guides/vault-structure/) para ver el layout esperado
- **Opcional para delegación de tareas:** cualquier endpoint `/v1` compatible con OpenAI — un servicio alojado o un runtime en tu propia máquina. Necesitas su URL base, una credencial si la requiere y un id de modelo. Hive no nombra ningún proveedor.

## Instalación

Un solo comando. Sin clonar, sin venv, sin archivos de configuración.

:::tip[Usa scope de usuario]
Registra siempre Hive a nivel de **usuario** (no de proyecto) para que funcione en todos tus proyectos. Ese es el objetivo — un vault, todos los proyectos.
- **Claude Code:** flag `-s user`
- **Gemini CLI:** flag `-s user`
- **Codex CLI / Copilot / OpenCode:** los archivos de config ya son a nivel de usuario (`~/.codex/config.toml`, `~/.config/opencode/opencode.jsonc`) o se pueden agregar a la configuración de usuario de VS Code
:::

<Tabs syncKey="client">
  <TabItem label="Claude Code">
    ```bash
    claude mcp add -s user hive -- uvx --upgrade hive-vault
    ```
  </TabItem>
  <TabItem label="Codex CLI">
    Agrega a `~/.codex/config.toml`:
    ```toml
    [mcp_servers.hive-vault]
    command = "uvx"
    args = ["--upgrade", "hive-vault"]
    ```
  </TabItem>
  <TabItem label="Gemini CLI">
    ```bash
    gemini mcp add -s user hive-vault uvx -- --upgrade hive-vault
    ```
  </TabItem>
  <TabItem label="Copilot (VS Code)">
    Agrega a `.vscode/mcp.json` en tu proyecto:
    ```json
    {
      "servers": {
        "hive-vault": {
          "command": "uvx",
          "args": ["--upgrade", "hive-vault"]
        }
      }
    }
    ```
  </TabItem>
  <TabItem label="OpenCode">
    Agrega a `~/.config/opencode/opencode.jsonc`:
    ```jsonc
    {
      "mcp": {
        "hive": {
          "type": "local",
          "command": ["uvx", "--upgrade", "hive-vault"],
          "enabled": true
        }
      }
    }
    ```
  </TabItem>
</Tabs>

El flag `--upgrade` asegura que siempre obtengas la última versión de PyPI al iniciar cada sesión. `uvx` gestiona el entorno Python automáticamente.

## Actualizar una instalación persistente

Las configuraciones con `uvx` anteriores resuelven la versión actual en cada nueva sesión. Si
usas una instalación persistente para el [modo daemon](/hive/es/guides/daemon-mode/), actualízala
de forma deliberada:

```bash
# Linux / macOS
uv tool upgrade hive-vault

# Windows (la versión es opcional; al omitirla se selecciona la última versión de PyPI)
hive self-upgrade [version]
```

En Windows, `self-upgrade` construye la nueva release junto a los archivos activos y cambia el
runtime gestionado de forma atómica, sin modificar archivos retenidos por un proceso de Hive en
ejecución. Abre una terminal nueva tras la primera actualización gestionada para disponer del
launcher añadido a tu `PATH` de usuario. Inicia una nueva sesión MCP tras cualquier actualización;
una sesión existente mantiene su proceso de servidor actual.

## Primera Consulta

Una vez registrado, tu asistente de IA puede usar las herramientas de Hive. Prueba preguntando:

> "Usa vault_list para ver mi vault"

El asistente llamará a `vault_list()` y listará todos los proyectos con recuento de archivos y atajos disponibles.

## Configurar Ruta del Vault

Por defecto, Hive busca tu vault en `~/Projects/knowledge`. Si esta ruta no existe, las herramientas de vault devolverán un error con instrucciones de configuración — el servidor sigue arrancando, así que las herramientas de worker permanecen disponibles.

Para apuntar Hive a tu vault:

<Tabs syncKey="client">
  <TabItem label="Claude Code">
    ```bash
    claude mcp add -s user hive -e VAULT_PATH=/ruta/a/tu/vault -- uvx --upgrade hive-vault
    ```
  </TabItem>
  <TabItem label="Codex CLI">
    ```toml
    [mcp_servers.hive-vault]
    command = "uvx"
    args = ["--upgrade", "hive-vault"]

    [mcp_servers.hive-vault.env]
    VAULT_PATH = "/ruta/a/tu/vault"
    ```
  </TabItem>
  <TabItem label="Gemini CLI">
    ```bash
    gemini mcp add -s user -e VAULT_PATH=/ruta/a/tu/vault hive-vault uvx -- --upgrade hive-vault
    ```
  </TabItem>
  <TabItem label="Copilot (VS Code)">
    ```json
    {
      "servers": {
        "hive-vault": {
          "command": "uvx",
          "args": ["--upgrade", "hive-vault"],
          "env": {
            "VAULT_PATH": "/ruta/a/tu/vault"
          }
        }
      }
    }
    ```
  </TabItem>
  <TabItem label="OpenCode">
    ```jsonc
    {
      "mcp": {
        "hive": {
          "type": "local",
          "command": ["uvx", "--upgrade", "hive-vault"],
          "environment": {
            "VAULT_PATH": "/ruta/a/tu/vault"
          },
          "enabled": true
        }
      }
    }
    ```
  </TabItem>
</Tabs>

## Configurar Worker (Opcional)

Para habilitar la delegación de tareas, apunta Hive a un único endpoint compatible con OpenAI con `HIVE_WORKER_BASE_URL`, `HIVE_WORKER_API_KEY` y `HIVE_WORKER_MODEL`. Sin URL base el worker queda deshabilitado y `delegate_task` indica al host que gestione la tarea por sí mismo:

<Tabs syncKey="client">
  <TabItem label="Claude Code">
    ```bash
    claude mcp add -s user hive \
      -e VAULT_PATH=/ruta/a/tu/vault \
      -e HIVE_WORKER_BASE_URL=https://api.your-provider.example/v1 \
      -e HIVE_WORKER_API_KEY=<your-key> \
      -e HIVE_WORKER_MODEL=<model-id> \
      -- uvx --upgrade hive-vault
    ```
  </TabItem>
  <TabItem label="Codex CLI">
    ```toml
    [mcp_servers.hive-vault]
    command = "uvx"
    args = ["--upgrade", "hive-vault"]

    [mcp_servers.hive-vault.env]
    VAULT_PATH = "/ruta/a/tu/vault"
    HIVE_WORKER_BASE_URL = "https://api.your-provider.example/v1"
    HIVE_WORKER_API_KEY = "<your-key>"
    HIVE_WORKER_MODEL = "<model-id>"
    ```
  </TabItem>
  <TabItem label="Gemini CLI">
