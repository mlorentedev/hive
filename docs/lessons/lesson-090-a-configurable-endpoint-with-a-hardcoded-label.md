# A configurable endpoint with a hardcoded label states a fact it does not know

**Context:** 4.0.0 made the worker provider-neutral by construction — `HIVE_WORKER_BASE_URL` / `_MODEL` / `_API_KEY`, OpenAI-compatible, empty default meaning *disabled* rather than a guessed endpoint. That part was right, and it is what makes the defect easy to miss: the mechanism was neutral while the vocabulary was not.
**Problem:** Two leaks shipped to PyPI, and they point in opposite directions. **Outward:** `server.py` built the worker client with `provider_name="NaN"` as a literal, not derived from configuration. `provider_name` feeds every error string in `clients.py` (`f"{self._provider_name} unavailable: {exc}"`), so whatever endpoint an operator configured, hive labelled it with one deployment's provider — in errors, in `worker_status`, in `usage.db` telemetry. **Inward:** `config.py` accepted `NAN_API_KEY` as a validation alias, making a published package read an environment variable that means something in exactly one private deployment. Each half looked reasonable alone: the label had to say *something*, and the alias had a real justification (the consuming launcher resolved the credential under that name, and without the alias authentication would fail for a reason no error explains). A dead `X-OpenRouter-Title` request header survived the same way — a parameter no caller passed, sent to a provider that no longer existed.
**Solution:** Derive the label instead of declaring it — `provider_label(base_url)` returns the host, falling back to a generic string when the URL carries none, so the name in an error is always the machine the request actually went to. Drop the alias outright: mapping a launcher's own variable name onto `HIVE_WORKER_API_KEY` is the *launcher's* job, at injection time. Verify before choosing `fix` over `fix!` — the alias had no possible consumer, because a worker only constructs when `HIVE_WORKER_BASE_URL` is set and no deployment set it (checked `environment.d`, the systemd unit and its optional `EnvironmentFile`). Guard it with `tests/test_provider_neutrality.py`, which scans the modules that configure or describe a client for brand names and asserts the alias stays gone; `_workers.py` is deliberately outside that scan, because *rejecting the retired aliases by name* is its behaviour.
**Why:** The test that catches both halves is one question — **does this remain true if someone else deploys it?** A `base_url` the operator sets, paired with a label the package fixes, fails it, even though each half reads as reasonable on its own. This is what separates a published package from an internal one: internally the label was accurate, so nothing was wrong until the audience changed, and no test notices an audience change. The general form: **configuration is a contract outward, a literal is an assertion inward, and a surface that mixes them will describe one deployment to everyone.** Corollary for the derivation choice — a label configured separately from the endpoint it names is a second thing to keep truthful, and it goes stale the moment someone repoints the endpoint without updating it; deriving costs one function and cannot disagree.
